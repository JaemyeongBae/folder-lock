# 폴더 잠금 설계 (2026-09-25 확정: A 방식, Windows·macOS)

## 목표와 위협 모델
- 등록한 폴더를 잠그면, 비밀번호로 풀기 전까지 내부 파일이 보이지 않는다.
- **막는 대상: 주변 사람(가족·동료)의 우연한 열람.** 관리자 권한이 있고 방법을 아는 사람은 풀 수 있다 (사용자 결정).
- 최우선 원칙: 어떤 버그·강제 종료·정전에도 파일이 사라지지 않는다.

## 방식: 이동 + 숨김 + 접근 차단 (파일 내용은 건드리지 않음)
잠그면 폴더 구조가 이렇게 바뀐다.

```
내 폴더\
  잠금 해제.exe          ← 이 앱의 사본. 실행하면 비밀번호 창이 뜬다
  .folderlock\           ← 숨김+시스템 속성, Everyone 목록 보기·삭제 거부
     meta.json           ← 상태, 비밀번호 해시(Argon2id), 잠금 해제 exe의 SHA-256
     data\               ← 목록 보기·삭제 거부. 원래 항목이 전부 여기로 옮겨짐
```

- 옮기기는 **최상위 항목 단위의 이름 바꾸기(MoveFileExW, 플래그 0)** 로만 한다.
  - 같은 볼륨 안에서만 동작한다. 복사+삭제로 바뀌는 일은 없다 (COPY_ALLOWED 플래그 없음).
  - 대상이 있으면 실패한다. 덮어쓰지 않는다 (REPLACE_EXISTING 플래그 없음).
  - 폴더는 통째로 한 번에 옮겨진다. 하위 파일이 수만 개여도 작업 수는 최상위 항목 수와 같다.
- 거부 ACE는 Everyone에 대해 `FILE_LIST_DIRECTORY | DELETE | FILE_DELETE_CHILD`만 막는다.
  소유자는 권한(DACL)을 항상 바꿀 수 있으므로, 앱은 이 ACE를 언제든 되돌릴 수 있다.

### macOS
- 이동: `renamex_np(RENAME_EXCL)` — 같은 볼륨 안에서만, 덮어쓰기 금지.
- 숨김: Finder 숨김 플래그(`UF_HIDDEN`) + 점으로 시작하는 이름.
- 차단: 권한 `0o300`(목록 보기 불가) + 잠금 플래그 `uchg`(삭제·이름 바꾸기·항목 추가/삭제 불가, root의 `rm`도 거부).
- 잠금 해제 입구: `잠금 해제.app` — 설치된 앱(`com.jmmi.folderlock`)을 `--unlock-folder <폴더>`로 여는 스크립트 앱.
  앱이 설정 폴더에 고정된 내용으로 만들어 두고 복사한다. 폴더형이라 해시는 하위 항목 전체의 트리 해시.
- 허용 볼륨: 로컬 APFS/HFS+. iCloud "데스크탑 및 문서" 동기화가 켜져 있으면 데스크탑·문서 아래 전체를 거부.

### 잠금 해제 입구 넣기·빼기
- 넣을 때: 보관 폴더 안 `entry.tmp`에 다 복사한 뒤 한 번에 폴더로 옮긴다.
- 뺄 때: 해시를 확인한 뒤 한 번에 `entry.tmp`로 옮기고 지운다.
- 도중에 꺼져도 반쯤 된 입구는 보관 폴더 안에만 남고, 다음 작업 때 정리된다.

## 안전 규칙
1. **이동만 한다.** 사용자 파일을 복사하거나 암호화하거나 덮어쓰지 않는다.
2. **지우는 것은 앱이 만든 것뿐이다.** meta.json(.tmp), 빈 디렉터리, 해시가 일치하는 잠금 해제 입구, 보관 폴더 안의 `entry.tmp`.
   빈 디렉터리 삭제는 비어 있지 않으면 OS가 거부한다.
3. **상태를 먼저 기록하고 움직인다.** meta.json은 임시 파일에 쓰고 디스크에 내린 뒤 교체한다.
4. **실패하면 되돌린다.** 잠그다 한 항목이라도 실패하면(예: 사용 중인 파일) 전부 원래 자리로 돌려놓는다.
5. **중단되면 이어서 끝낸다.** 앱을 다시 켜면 `Locking`은 마저 잠그고, `Unlocking`은 마저 푼다.
6. **풀 때 이름이 겹치면 이름을 바꿔 복원한다.** 잠긴 동안 같은 이름 파일이 생겼다면 `보고서 (복원 1).docx`처럼 복원한다.
7. **위험한 폴더는 거부한다.**
   - 드라이브 루트, Windows 폴더, Program Files, ProgramData, AppData
   - 사용자 폴더 자체와 바탕 화면·문서·다운로드 등 (단, 그 하위 폴더는 허용)
   - 동기화 폴더: OneDrive, Dropbox, iCloudDrive, Google Drive, MYBOX (macOS는 ~/Library 전체 포함)
   - 네트워크 폴더, NTFS가 아닌 드라이브(USB 메모리 등), 링크·정션 폴더
   - 앱 exe나 앱 설정 폴더를 품은 폴더, 이미 등록된 폴더와 겹치는 폴더

## 상태
| 상태 | 뜻 | 처리 |
|---|---|---|
| 열림 | `.folderlock` 없음 | |
| 잠김 | meta.state = locked | 앱 시작 시 숨김·차단 재적용 |
| 중단됨 | locking / unlocking | 앱 시작 시 자동으로 이어서 마침 |
| 정리 필요 | 보관 폴더가 비었고 meta 없음 | 자동 정리 |
| 손상 | 보관 폴더에 항목이 있는데 meta 없음 | 설정의 예비 해시로 해제, 또는 비상 복원('복원' 입력) |

## 알려진 한계
- 관리자 권한이 있는 사람은 소유권·권한을 바꿔 열 수 있다 (의도된 한계).
- Windows 검색 색인, 최근 항목, 썸네일 캐시에 파일 이름이 남아 있을 수 있다.
- 서명되지 않은 exe라 처음 실행할 때 SmartScreen 경고가 뜰 수 있다.
- 잠긴 폴더를 휴지통으로 보내면 폴더째 휴지통으로 간다. 파일은 그 안에 그대로 있다 (보관 폴더는 삭제 거부).
- 앱을 두 개 동시에 켜고 같은 폴더를 조작하는 경우는 막지 않는다.

## 구조
- `src/engine.rs` 잠그기·풀기·복구 (OS 무관)
- `src/platform/` 이동·숨김·차단 (Windows ACL / macOS 권한+플래그)
- `src/mac_entry.rs` macOS 잠금 해제 입구(.app) 생성
- `src/guard.rs` 금지 폴더 규칙
- `src/config.rs` 등록 목록 `%APPDATA%\FolderLock\config.json`, 작업 로그 `log.txt`
- `src/main.rs` 앱 상태·동작, `src/ui/` 화면 (egui: 테마·직접 그린 아이콘·위젯·화면)
- `assets/fonts/` Pretendard (SIL OFL 1.1) — 앱에 내장
- `tests/engine.rs` 결함 주입 테스트

## 테스트 (Mac에서 자동 실행)
- 무작위 폴더 트리 40종: 잠금 → 해제 후 바이트 단위 동일
- **모든 작업 단계에서 강제 종료** (잠그기·풀기·되돌리기·복구 도중 재중단): 중단 직후 유실 없음 + 복구 후 원본과 동일
- 각 단계의 일시적 오류: 전부 되돌려짐
- 사용 중 파일, 이름 충돌, 잠금 해제 exe 변조, 상태 파일 손상, 금지 폴더
- macOS 구현은 이 테스트가 실제 플랫폼 코드(권한·잠금 플래그 포함)로 돈다. 폴더 안 `잠금 해제.app` → 비밀번호 → 복원까지 실기 확인 완료.
- 한계: Windows ACL·속성 코드는 Mac에서 돌지 않으므로 Windows 실기 테스트가 필요하다 → `docs/윈도우-테스트.md`
